## 1) ما الذي نحتاجه لكل طبعة

التطبيق **لا يخزّن نص القرآن إطلاقًا** — ولا آية واحدة. كل ما يحتاجه هو **ترقيم الصفحات**:

| المفتاح | الطول | المعنى |
|---|---|---|
| `N` | — | رقم **آخر** صفحة في المصحف |
| `P0` | — | رقم **أول صفحة فيها نص** (1 عادةً، 2 في الشمرلي لأن الصفحة 1 غلاف) |
| `SS` | 114 | أول صفحة لكل سورة |
| `SE` | 114 | آخر صفحة لكل سورة |
| `RS` | 240 | أول صفحة لكل ربع حزب |
| `RE` | 240 | آخر صفحة لكل ربع حزب |
| `RSA` | 240 | الآية `[سورة، آية]` التي يبدأ عندها كل ربع |
| `JS` | 30 | أول صفحة لكل جزء |
| `JE` | 30 | آخر صفحة لكل جزء |
| `label` / `short` | — | اسم الطبعة الكامل والمختصر (يُعرضان في كل القوائم) |

**عدد الصفحات التي تُقاس بها النسبة** = `N - P0 + 1` (المدينة: 604، الشمرلي: 521).

## 2) مصحف المدينة النبوية (604 صفحة)

### المصدر

**حزمة `quran-meta`** على npm — [github.com/quran-center/quran-meta](https://github.com/quran-center/quran-meta)

* الرخصة: **MIT**
* الاعتماديات: **صفر**
* الإصدار المستعمل: **7.0.0** (مثبّت في `package-lock.json`)
* تحتوي ترقيم صفحات المصحف السعودي (حفص عن عاصم، 604 صفحة) لكل آية من الـ6236،
  بالإضافة إلى الأجزاء والأحزاب والأرباع والأركان والمنازل والسجدات، لثماني روايات.

### التوليد

```bash
npm install                   # مرة واحدة
node tools/gen_madinah.mjs            # يقارن بالبيانات المحفوظة
node tools/gen_madinah.mjs --write    # يكتب في data/editions.json
```

الخوارزمية — **مرور واحد على كل الـ6236 آية**:

```js
const hafs = createHafs();
for (let id = 1; id <= hafs.meta.numAyahs; id++) {
  const m = hafs.getAyahMeta(id);          // {page, surah, ayah, juz, rubAlHizbId, …}
  if (!SS[m.surah-1])       SS[m.surah-1]       = m.page;   SE[m.surah-1]       = m.page;
  if (!RS[m.rubAlHizbId-1]) { RS[m.rubAlHizbId-1] = m.page; RSA[m.rubAlHizbId-1] = [m.surah, m.ayah]; }
                            RE[m.rubAlHizbId-1] = m.page;
  if (!JS[m.juz-1])         JS[m.juz-1]         = m.page;   JE[m.juz-1]         = m.page;
}
```

**مفيش أي تقدير ولا استنتاج** — الحزمة بتدينا صفحة كل آية مباشرة، فالنهايات والبدايات كلها دقيقة.

## 3) مصحف الشمرلي (522 صفحة)

### المصدر

**مستودع `Mr-DDDAlKilanny/Shamarly`** على GitHub (عام) — الملف `shamerly.db` (~9 ميجابايت).

```bash
# الطريقة اللي بتنزّل بيها الأداة تلقائيًا:
curl -sS -L -H "Accept: application/vnd.github.raw" \
  -o shamerly.db \
  "https://api.github.com/repos/Mr-DDDAlKilanny/Shamarly/contents/shamerly.db"
```

> ⚠️ `raw.githubusercontent.com` **مش متاح** في بعض بيئات التطوير المقيّدة. الطريقة أعلاه
> (عبر `api.github.com`) بتشتغل لحد ~100 ميجابايت.

### بنية القاعدة

```sql
CREATE TABLE "mushaf" (
  page       int NOT NULL,     -- رقم الصفحة المطبوعة (2..522)
  sura       int NOT NULL,
  ayah       int NOT NULL,
  x          int NOT NULL,     -- إحداثي علامة رقم الآية في صورة الصفحة
  y          int NOT NULL,     -- (الصورة 886×1377، الأصل أعلى اليسار)
  ayah_index INTEGER,
  ayahtext   TEXT,
  tafseer    TEXT,
  PRIMARY KEY (sura ASC, ayah ASC)
);
```

**6238 صفًا** = 6236 آية + صفّان بـ`ayah=0` (علامتا البسملة في الصفحتين 2 و3).

### ⚠️ ثلاثة أفخاخ في هذا المصدر

1. **`page` هي صفحة _نهاية_ الآية، مش بدايتها.**
   (تحقّق منه مشروع `tibyan` لكل الـ6236 آية — انظر أدناه.)
2. **لا تعتمد على `ayah_index`.** قيمته **نص فاضي** (`''`) للآية `(1,1)`، فأي
   `ORDER BY ayah_index` بيحط الفاتحة في **آخر** القائمة.
   **الترتيب الصحيح هو `ORDER BY sura, ayah`** (وهو ترتيب المفتاح الأساسي).
   > ده كان سبب فرقَين في أول محاولة تشغيل للأداة الجديدة.
3. **استثنِ صفوف `ayah=0`** — علامات البسملة مش آيات.

### التوليد

```bash
python3 tools/gen_shamarly.py                 # ينزّل المصدر مرة واحدة في ~/.cache/shamarly/
python3 tools/gen_shamarly.py --db /path/shamerly.db
python3 tools/gen_shamarly.py --report        # + الحالات القريبة من العتبات
python3 tools/gen_shamarly.py --write         # يكتب في data/editions.json
```

#### النهايات — دقيقة 100% (بلا أي تقدير)

```python
SE[i] = end[(i+1, آخر_آية_في_السورة)]                 # صفحة نهاية آخر آية
RE[i] = end[prev[RSA[i+1]]]   for i < 239              # صفحة نهاية الآية السابقة لأول آية في الربع التالي
RE[239] = end[(114, 6)]
JE[j] = RE[8j+7]
```

| الفحص | النتيجة |
|---|---|
| 114 نهاية سورة (`SE`) مقابل صفحة نهاية آخر آية | **0 اختلاف** |
| 240 نهاية ربع (`RE`) مقابل صفحة نهاية الآية السابقة | **0 اختلاف** |
| `JS[j] == RS[8j]` و`JE[j] == RE[8j+7]` | **0 اختلاف** |

#### البدايات — تحتاج تقديرًا (موثّق ومُختبَر)

القاعدة **لا تقول أين تبدأ الآية التي تمتد على صفحتين**. القاعدة المستعملة:

```python
def surah_start(sa):
    e  = end[sa]                       # صفحة نهاية الآية الأولى من السورة
    if sa == (1,1): return 2           # الفاتحة: الصفحة 2 (بعد الغلاف) — ثابت
    if sa == (2,1): return 3           # البقرة: الصفحة 3 المزخرفة — ثابت
    pe = end[prev[sa]]                 # صفحة نهاية الآية السابقة
    if pe == e:  return e              # الآية لا تمتد على صفحتين
    x, y = pos[prev[sa]]
    return pe if y <= 940 else e       # علامة السابقة في أعلى الصفحة ⇒ ما زال فيها متّسع

def rub_start(sa):
    e  = end[sa]
    if sa not in prev: return e
    pe = end[prev[sa]]
    if pe == e:  return e
    x, y = pos[prev[sa]]
    return e if x <= 104 else pe       # علامة السابقة عند اليسار ⇒ السطر/الصفحة اكتملت
```

**لماذا هاتان العتبتان؟** مستخرجتان من البيانات نفسها، وبتفصل الحالتين **تمامًا**:

| الحالة | العدد | مدى `x` | مدى `y` |
|---|---|---|---|
| بداية في صفحة **جديدة** (`E`) | 15 | **6 … 104** | 1111 … 1307 |
| بداية في **نفس** الصفحة (`PE`) | 22 | **105 … 751** | 1021 … 1306 |

يعني `x ≤ 104 → E` و`x ≥ 105 → PE` بتعيد إنتاج **كل الـ37 حالة** الممتدة بلا أي اختلاف.

> ⚠️ **الهامش رفيع (104 مقابل 105)** — عشان كده الأداة بتطبع الحالات القريبة من العتبة
> تلقائيًا في **كل** تشغيل. انظر [§6](#6-ما-يحتاج-مراجعة-بشرية).

**المعنى الفيزيائي:** `x` هو موضع علامة رقم الآية، والصفحات تُقرأ من اليمين لليسار. الآية
التي تنتهي عند `x` صغير يعني السطر **اكتمل**. لو ده آخر سطر في الصفحة فالصفحة **مليانة** →
الآية التالية تبدأ في صفحة جديدة.

## 4) أدوات التحقق الثلاث

| الأداة | تحتاج تنزيل؟ | ماذا تفحص | متى تشغّلها |
|---|---|---|---|
| `tools/verify_editions.py` | **لا** (Python القياسية فقط) | 30+ فحص بنيوي + مراجع مطبوعة + **التحويل بين الطبعات** | كل مرة، وفي CI |
| `node tools/gen_madinah.mjs` | نعم (`npm install`) | يولّد المدينة من `quran-meta` ويقارن قيمة بقيمة | عند أي شك في بيانات المدينة، وفي CI |
| `python3 tools/gen_shamarly.py` | نعم (ينزّل 9 م.ب مرة واحدة) | يولّد الشمرلي من `shamerly.db` ويقارن قيمة بقيمة | عند أي شك في بيانات الشمرلي |

### `verify_editions.py` بالتفصيل

1. **البنية:** كل الحقول موجودة، والأطوال 114/114/240/240/240/30/30.
2. **الحدود:** كل رقم صفحة داخل `[P0, N]`، وكل بداية ≤ نهايتها.
3. **الرتابة:** `SS`/`SE`/`RS`/`RE`/`JS`/`JE` غير متناقصة، و`JS` **متزايدة تمامًا**.
4. **التغطية:** السور والأرباع والأجزاء تغطي `P0..N` بلا فجوات.
5. **الاتساق الداخلي:** `JS[j] == RS[8j]` و`JE[j] == RE[8j+7]`.
6. **اتساق بين الطبعات:** `RSA` **متطابقة** في كل الطبعات (النص والتقسيم واحد).
7. **مراجع مطبوعة:** 15 مرجعًا لكل طبعة + بدايات الأجزاء الثلاثين لكل طبعة.
8. **التحويل بين الطبعات:** يعيد تنفيذ `mapPage` (نفس دالة `src/app.js`) بـPython ويتأكد إنه:
   * **رتيب** (لا يرجع لوراء أبدًا)،
   * **يثبّت الطرفين** (`P0(A) → P0(B)` و`N(A) → N(B)`)،
   * **الذهاب والإياب** لا يباعد أكثر من 3 صفحات.

**النتيجة الحالية:**

```
· [madinah↔shamarly] التحويل رتيب ويثبّت الطرفين، وأكبر انحراف في الذهاب والإياب 2 صفحة (عند 383)
· [shamarly↔madinah] التحويل رتيب ويثبّت الطرفين، وأكبر انحراف في الذهاب والإياب 1 صفحة (عند 10)
✓ data/editions.json سليم (2 طبعات: madinah, shamarly)
```

### التحقق في CI

`.github/workflows/ci.yml` بيشغّل في كل push وPR:

1. `python3 tools/verify_editions.py -v`
2. `python3 tools/build.py --check` — يفشل لو `index.html` مش محدّث
3. `node tools/gen_madinah.mjs` — يفشل لو بيانات المدينة اتغيّرت عن مصدرها
4. الاختبارات الخمسة (273 فحصًا)
5. فحص استقلال `index.html` (مفيش موارد خارجية)

> `gen_shamarly.py` **مش** في الـCI لأنه بينزّل 9 ميجابايت. شغّله يدويًا عند الحاجة.

## 6) ما يحتاج مراجعة بشرية

### الحالات الحرجة في بدايات أرباع الشمرلي

`gen_shamarly.py` بتطبعها تلقائيًا في كل تشغيل (وتظهر كمان مع `--report`):

| الربع | الآية | علامة الآية السابقة | النتيجة | المطلوب |

## 7) حقائق تصميمية

### الصفحات المشتركة بين الوحدات

مجموع صفحات الأجزاء **أكبر** من عدد صفحات المصحف:

| | مجموع صفحات الأجزاء | صفحات المصحف | الفرق |
|---|---|---|---|
| المدينة | 608 | 604 | 4 حدود مشتركة (الأجزاء 4/7/11/26) |
| الشمرلي | 548 | 521 | 28 من 29 حدًا مشتركًا |

**ده مقصود وصحيح.** الصفحة التي فيها آخر آية من جزء وأول آية من الجزء التالي تظهر في
بطاقتَي الجزءين — عشان كده الجزء 3 بيظهر «42 – 62» والجزء 4 «62 – 81».

`applyAdd` بتمنع إن الصفحة دي **تتحسب مرتين** في `read`: بترجع الصفحات **الجديدة فعلًا** فقط.

### الأرباع هي وحدة التحويل بين الطبعات

`mapPage(p, from, to)` بتحوّل صفحة من طبعة لطبعة **بالاستيفاء داخل الربع نفسه**:

```js
// 1) دور على الربع اللي فيه الصفحة p في الطبعة A
// 2) احسب موضعها النسبي داخل الربع:  f = (p - A.RS[r]) / (A.RE[r] - A.RS[r])
// 3) طبّق نفس النسبة على الربع المقابل في الطبعة B
return clamp(Math.round(B.RS[r] + clamp(f,0,1) * (B.RE[r] - B.RS[r])), B.P0, B.N);
```

**لماذا الأرباع؟** لأنها أدقّ تقسيم مشترك بين كل الطبعات (240 في أي مصحف)، فالخطأ ما
يتعدّى نصف ربع ≈ صفحة أو صفحتين. و`verify_editions.py` بيقيس ده فعليًا: **أكبر انحراف في
الذهاب والإياب = 2 صفحة**.

> **تحذير:** التحويل **تقريبي**. التطبيق بيقول كده صريحًا للمستخدم في رسالة التأكيد:
> *«ولن تتطابق الصفحات تمامًا لأن الطبعتين مختلفتان»*. وبعدها بينصحه
> *«راجع آخر صفحة وصلت إليها»*.

### `RSA` واحدة لكل الطبعات

`RSA` هي **الآيات** التي تبدأ عندها الأرباع — ودي **مش بتختلف** بين الطبعات (النص القرآني
وتقسيم الأرباع واحد؛ اللي بيختلف هو في أي **صفحة** بتطبع كل آية). `verify_editions.py`
بيفشل لو `RSA` اختلفت بين طبعتين.

عشان كده `gen_shamarly.py` بتقرأ `RSA` **من بيانات المدينة** بدل ما تحاول تستنتجها.

## 8) إضافة طبعة ثالثة

دلوقتي بقت **سهلة جدًا** — مفيش سطر كود يتغيّر.

### الخطوات

1. **اجمع البيانات** (114 + 114 + 240 + 240 + 240 + 30 + 30 قيمة) من مصدر موثوق.
   الأسهل: قاعدة بيانات فيها صفحة كل آية، زي `shamerly.db`.
2. **اكتب أداة توليد** في `tools/gen_<name>.py` (انسخ `gen_shamarly.py` وعدّل المصدر).
3. **أضف مفتاحًا جديدًا** في `data/editions.json`:
   ```jsonc
   "newedition": {
     "label": "الاسم الكامل اللي يتعرض في القوائم",
     "short": "اسم مختصر للأزرار",
     "N": 604,
     "P0": 1,
     "SS": […], "SE": […], "RS": […], "RE": […],
     "RSA": [ … نفس RSA الموجودة في madinah حرفيًا … ],
     "JS": […], "JE": […]
   }
   ```
4. **شغّل:**
   ```bash
   python3 tools/verify_editions.py -v   # لازم ✓
   python3 tools/build.py                # إعادة البناء
   npm test                              # 273 فحصًا
   ```
5. **أضف مراجعها المطبوعة** في `verify_editions.py` → `ANCHORS` و`CANON_JUZ`.

### ما الذي سيحدث تلقائيًا

* `<select id="oEd">` في شاشة الترحيب — **بيتولّد من البيانات** (`edOptionsHTML`)
* أزرار الطبعة في الإعدادات — **بتتولّد من البيانات** (`edButtonsHTML`)
* كل رسائل الأخطاء («رقم الصفحة في **X** بين **P0** و **N**»)
* نطاقات كل مداخل الصفحات (`min`/`max`)
* التحويل التقريبي بينها وبين الطبعات الموجودة (`mapPage` عام)

### ما الذي يحتاج انتباهك

* **ترتيب المفاتيح في `EDS` مهم**: `ED_ORDER = Object.keys(EDS)`، و**الطبعة الأولى هي
  الافتراضية**. `madinah` لازم تفضل الأولى.
* **`P0`**: لو الطبعة فيها غلاف أو صفحات مقدّمة، اضبط `P0` على أول صفحة فيها نص قرآني.
* **الترحيل**: إضافة طبعة جديدة **ما تحتاجش** ترحيل — بيانات المستخدمين الموجودة مش بتتأثر.
  بس لو غيّرت ترقيم طبعة **موجودة**، لازم ترفع `v` في `defaultState()` وتكتب ترحيلًا في
  `sanitize()`. انظر [§8 في HANDOVER.md](../HANDOVER.md#8-ترقيم-الشمرلي) لمثال حي.
