# رحلتي مع القرآن

لوحة متابعة شخصية لقراءة القرآن وختماته — **عربية RTL**، **ملف HTML واحد**، تعمل **دون اتصال**،
وتحفظ بياناتك **في متصفحك أنت فقط**.

📖 **التوثيق الكامل للمشروع في [`HANDOVER.md`](HANDOVER.md)** — كل عطل اتكشف وإزاي اتصلح،
وكل قرار، وقائمة العمل المفتوحة. ابدأ من هناك.

---

## جرّبها

نزّل [`index.html`](index.html) وافتحه في أي متصفح. خلاص — مفيش تثبيت ولا سيرفر ولا إنترنت.

أو افتح الموقع المنشور على Vercel.

## ماذا فيها؟

* **حلقة تقدّم** للختمة الحالية مع علامات الأجزاء الثلاثين.
* **قراءة اليوم** مقابل هدفك (يومي أو بتاريخ مستهدف).
* **مؤشران للقراءة**: الصفحة التالية بعد آخر تسجيل، وأول صفحة فاضية من أول المصحف.
* **تسجيل بأي وحدة**: صفحات، سورة، جزء، حزب، ربع — مع منع العدّ المزدوج.
* **خريطة قراءة** 52 أسبوعًا + رسوم بيانية يومية/أسبوعية/شهرية + مسار تقدّم الختمة مع خط التوقع.
* **114 سورة** بشريط إنجاز لكل سورة + بحث.
* **سجل كامل** للتسجيلات قابل للتعديل والحذف والتراجع، وسجل لكل الختمات.
* **7 لوحات ألوان** + ثيم فاتح/داكن/تلقائي + كثافة + 3 أحجام خط.
* **تصدير/استيراد** نسخة احتياطية، وترحيل تلقائي للبيانات القديمة.
* **مشاركة التقدم برابط** — ابعث تقدمك لأي حد أو لجهازك التاني من غير سيرفر ولا حساب.
* **مصحفان**: المدينة النبوية (604 صفحة) والشمرلي المصري (522 صفحة)، مع تحويل تقريبي للتقدم بينهما.
* **PWA**: يتثبّت على الشاشة الرئيسية ويشتغل دون اتصال.

## البيانات

| السؤال | الجواب |
|---|---|
| البيانات بتتحفظ فين؟ | في `localStorage` بتاع **متصفحك أنت**، على جهازك |
| على GitHub؟ | **لا** — GitHub فيه الكود فقط |
| على Vercel؟ | **لا** — Vercel بيقدّم ملفات ساكنة فقط، مفيش سيرفر ولا قاعدة بيانات |
| زائرَين بيتشاركوا؟ | **لا** — كل زائر ليه نسخة مستقلة تمامًا (لكن تقدر **تبعتله تقدمك في رابط** من الإعدادات ← مشاركة التقدم) |
| فيه طلبات شبكة؟ | **صفر** — وفيه فحص آلي بيمنع إضافة أي طلب |

> ⚠️ **مسح بيانات المتصفح = مسح تقدمك.** صدّر نسخة احتياطية كل فترة
> (الإعدادات → تصدير نسخة احتياطية).

## التطوير

```bash
npm install                        # مرة واحدة: jsdom + quran-meta

# عدّل هنا ↓ (3 ملفات مريحة للتطوير)
#   src/index.html · src/styles.css · src/app.js · data/editions.json

python3 tools/build.py             # يبني index.html (+ manifest + sw.js + icons)
npm test                           # 273 فحصًا آليًا
npm run ci                         # كل حاجة زي CI بالظبط
```

> **⚠️ لا تعدّل `index.html` يدويًا أبدًا** — هو ناتج بناء ويُستبدل بالكامل في كل مرة.

| الأمر | الوظيفة |
|---|---|
| `python3 tools/build.py` | البناء |
| `python3 tools/build.py --check` | يفشل لو `index.html` مش محدّث (للـCI) |
| `python3 tools/verify_editions.py -v` | تحقّق من البيانات (بلا تنزيل) |
| `python3 tools/check_offline.py` | يضمن الاستقلال التام (مفيش موارد خارجية) |
| `node tools/gen_madinah.mjs` | يولّد بيانات المدينة من `quran-meta` ويقارن |
| `python3 tools/gen_shamarly.py` | يولّد بيانات الشمرلي من `shamerly.db` ويقارن |
| `npm test` | الاختبارات الخمسة (273 فحصًا) |

## النشر

الموقع منشور على **Vercel** من فرع `main`. `vercel.json` بيخلّيه يُنشر **كموقع ثابت خالص**:
مفيش `npm install` ولا `npm run build` على Vercel — `index.html` أثر بناء متعمِل commit أصلًا،
وCI بيأكد إنه محدّث قبل أي دمج. يعني النشر = رفع الملفات وبس (أسرع وأقل عرضة للكسر).

> ⚠️ لو شلت `vercel.json`، Vercel هيشوف `package.json` ويعتبر المشروع Node ويشغّل
> install وbuild — وده **هيكسر النشر**.
